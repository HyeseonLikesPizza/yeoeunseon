> 문서 목적: 전투·잠입 기능을 구현하기 위한 공통 캐릭터, 장비, AI 상태, 인지, 판단, 행동 및 정보 공유 구조를 정의한다.  
> 문서 상태: 초안  
> 최종 수정: 2026-07-21  
> 상위 규칙: [전투·잠입 게임플레이 기획서](./전투·잠입%20게임플레이%20기획서.md)

## 1. 문서 경계

이 문서는 플레이 감각이나 밸런스 목표가 아니라 기능 간 책임과 데이터 흐름을 다룬다.

- 게임플레이 기획서: 플레이어가 무엇을 할 수 있고 어떤 결과를 경험하는가
- 기능 구조 기획서: 해당 결과를 만들기 위해 어떤 시스템과 상태가 필요한가

수치와 규칙이 충돌할 경우 게임플레이 기획서를 기준으로 한다.

주요 시스템:

- UI 및 인벤토리

- 총기 시스템

AI의 기본 실행 흐름:

> 인지 → 판단 → 행동 → 행동 완료 → 재인지

## 3. 공통 캐릭터 구조

플레이어와 적은 동일한 기반 캐릭터 기능을 공유한다.

공통 행동:

- 조준
- 발사 및 장비 사용
- 재장전
- 총기 교체
- 근접 공격
- 줍기
- 달리기
- 웅크리기
- 엎드리기
- 회피
- 낮은 장애물 넘기
- 높은 지형 오르기

플레이어 전용 행동:

- 투척무기 사용
- 붕대 사용
- 붙잡기
- 붙잡은 적과 이동
- 암살
- 좁은 공간 통과

AI는 플레이어와 동일한 일반 이동 기능을 사용할 수 있지만 좁은 공간을 웅크리거나 기어서 통과하지 않는다.

## 4. 행동 실행 구조

### 4.1 기본 원칙

AI는 현재 행동을 완료한 뒤에만 재인지한다.

```text
인지
  ↓
판단
  ↓
행동 실행
  ↓
행동 완료
  ↓
재인지
```

행동 중 새 인지정보가 들어오더라도 일반적으로 현재 행동을 교체하지 않는다. 정보는 임시로 기록하고 행동 완료 후 다음 인지 단계에서 사용한다.

### 4.2 강제 행동

플레이어의 직접 상호작용은 현재 행동을 취소하고 강제 행동을 발생시킬 수 있다.

- 피격
- 붙잡힘
- 암살
- 밀려남
- 사망

예시:

```text
사격 중 피격
  → 사격 행동 취소
  → 피격 모션 실행
  → 피격 모션 완료
  → 재인지
  → 재판단
```

피격 직후 바로 판단하지 않는다. 피격 모션 자체가 새로운 강제 행동이며, 이 행동까지 끝나야 재인지한다.

사망이나 암살처럼 캐릭터의 행동이 종료되는 강제 행동은 재인지 단계로 돌아가지 않는다.

## 5. 입력·인벤토리·장착 구조

### 5.1 총기 슬롯

인벤토리는 보유 총기 중 2개를 빠른 전환 슬롯으로 지정한다.

- 총기 키 첫 입력: 지정된 현재 총기를 장착
- 총기 키 재입력: 슬롯 1과 슬롯 2를 토글
- 새로운 총기가 추가돼도 빠른 전환 슬롯 수는 2개 유지

필요 데이터:

- 보유 총기 목록
- 빠른 전환 슬롯 1
- 빠른 전환 슬롯 2
- 현재 장착 총기
- 현재 총기 슬롯

### 5.2 장비 장착

- 투척 키: 현재 선택된 투척 장비 장착
- 붕대 키: 붕대 장착
- 공통 사용 입력: 장착 장비의 사용 로직 실행

현재 장착한 총기와 장비 정보는 UI가 공통 인터페이스를 통해 읽는다.

## 8. AI 상태 구조

### 8.1 상태

```text
Alert  = 경계
Search = 색적
Combat = 전투
```

### 8.2 전투 이력

각 AI는 다음 일방향 불리언 값을 가진다.

```text
HasEnteredCombat: bool
```

규칙:

- 초기값은 `false`다.
- 직접 플레이어를 발견해 전투에 진입하면 `true`가 된다.
- 그룹에서 전투 상태를 공유받아도 `true`가 된다.
- 한 번 `true`가 되면 해당 전투 구역이 초기화될 때까지 `false`로 돌아가지 않는다.

이는 값의 종류는 불리언이지만 양방향 토글이 아니라 한 번만 활성화되는 플래그다.

### 8.3 상태 전환

전투 이력이 없는 경우:

```text
경계 → 이상 징후 → 색적 → 일정 시간 정보 없음 → 경계
```

플레이어 또는 전투 정보를 확인한 경우:

```text
경계/색적 → 전투
HasEnteredCombat = true
```

전투 이후 플레이어 위치를 잃은 경우:

```text
전투 → 일정 시간 위치 확인 실패 → 색적
```

`HasEnteredCombat == true`인 AI는 색적에서 경계로 전환할 수 없다.

## 9. 최초 발견 반응 구조

전투 이력이 없는 AI가 플레이어를 시야로 처음 확정하면 다음 순서를 사용한다.

```text
플레이어 인지
  → 전투 상태 설정
  → HasEnteredCombat = true
  → 그룹 공유 정보 생성
  → 놀람 행동 선택
  → 놀람 행동 완료
  → 재인지
  → 공격/이동 판단
```

놀람 행동의 애니메이션 길이가 최초 반응 지연 역할을 한다. 별도의 추상적인 반응 지연 타이머는 사용하지 않는다.

이미 전투 이력이 있는 AI는 플레이어를 재발견하면 놀람 행동 없이 공격 또는 이동을 판단한다.

그룹 공유로 전투에 진입한 AI도 전투 이력이 활성화되므로 이후 직접 플레이어를 발견했을 때 놀람 행동을 수행하지 않는다.

## 10. 시야 인지 구조

### 10.1 처리 순서

1. 최대 감지 거리 검사
2. 수평·수직 시야각 검사
3. 플레이어 신체 지점까지 시야선 검사
4. 노출 비율 계산
5. 자세·이동·수풀·상태 보정 적용
6. 감지 수치 누적 또는 감소
7. 기준 도달 시 시각 인지정보 생성

### 10.2 시야 판정 지점

기본 검사 지점:

- 머리
- 가슴
- 골반

AI의 눈 위치에서 각 지점으로 시야선을 검사한다. 보이는 지점의 수와 가중치로 노출 정도를 계산한다.

필요 설정값:

- 지점별 가중치
- 몇 개의 지점이 보여야 감지가 시작되는지
- 머리만 보이는 경우의 감지 속도
- 엎드린 자세에서의 지점 보정

### 10.3 상태별 인지 프로필

상태별 감도는 단일 수치가 아니라 기본 시야·청각 데이터에 적용하는 보정 프로필이다.

- 경계: 기본 인지 성능
- 색적: 작은 변화와 소리에 조금 더 민감
- 전투: 플레이어 재발견이 빠르며 최초 놀람 행동 없음

상태별로 조정 가능한 값:

- 최대 시야 거리
- 시야각
- 감지 누적 속도
- 감지 감소 속도
- 청각 인지 임계값
- 마지막 시각정보 유지 방식

공통 기본값을 두고 차이가 필요한 값만 상태별로 덮어쓴다.

## 11. 청각 인지 구조

### 11.1 소리 자극 데이터

각 소리 이벤트는 다음 정보를 가진다.

- 소리 종류
- 발생 위치
- 발생 주체
- 기본 소리 거리
- 기본 소리 강도
- 거리 감쇠 정보
- 발생 시각
- 전투 정보 포함 여부
- 공유 정보 식별자

사용하지 않는 항목:

- 바닥 재질 보정
- 소리 위치 오차
- 일반적인 주변 물체 충돌음
- 장기적인 소리 기억 시간

벽돌, 폭탄처럼 의도적으로 소리를 만드는 오브젝트는 명시적인 소리 이벤트를 생성한다.

### 11.2 소리 계산

기본 소리 거리 밖의 AI는 계산 대상에서 제외한다.

```text
최종 소리 강도
= 기본 강도
× 이동 속도·자세 보정
× 거리 감쇠
× 장애물 감쇠
```

환경의 백색소음은 청각 인지 임계값을 높이는 보정으로 적용한다.

```text
최종 소리 강도 >= 상태별 청각 인지 임계값 + 환경소음 보정
```

조건을 만족할 때만 소리 인지정보를 생성한다. 임계값 미만의 소리는 저장하거나 누적하거나 공유하지 않는다.

소리 위치는 정확하게 전달한다. 정확한 소리 위치를 아는 것과 플레이어를 시각적으로 발견한 것은 별개의 정보다.

### 11.3 임시 소리 인지 버퍼

AI가 행동 중일 때 발생한 유효한 소리를 놓치지 않도록 다음 재인지까지 임시 버퍼에 보관한다.

- 임계값을 넘은 소리만 보관한다.
- 판단 전 여러 소리가 들어오면 가장 최신 소리를 사용한다.
- 발생 시각이 같으면 더 강한 소리를 사용한다.
- 판단 후 버퍼를 비운다.
- 선택한 조사 위치는 현재 행동 목적지로 복사한다.

이는 장기 기억이 아니라 현재 행동과 다음 재인지 사이를 연결하는 일회성 인지정보다.

### 11.4 상태별 반응

- 경계: 유효한 소리를 인지하면 색적을 판단한다.
- 색적: 최신 소리 위치로 조사 목표를 갱신한다.
- 전투: 이동, 엄폐, 측면 이동과 협력 판단의 위치 정보로 사용한다.

## 12. 동적 그룹 구조

### 12.1 개인 정보와 그룹 정보

모든 AI는 항상 개인 정보를 가진다.

개인 정보:

- 자신의 상태와 전투 이력
- 직접 본 위치
- 직접 들은 소리 위치
- 현재 행동과 목적지

전투 정보가 공유되면 그룹 정보가 생성된다.

그룹 정보:

- 그룹 전투 상태
- 최신 플레이어 위치
- 정보 종류
- 원본 정보 발생 시각
- 최초 정보 제공자
- 그룹 구성원
- 아군이 점유한 엄폐·이동 목적지
- 공동 색적 구역

### 12.2 음성 공유

그룹 공유는 플레이어에게 적의 목소리로 표현된다.

```text
AI가 플레이어 정보 인지
  → 공유 음성 발생
  → 주변 AI가 음성을 청각 판정
  → 임계값을 넘은 AI만 정보 수신
  → 그룹 형성 또는 병합
```

공유 음성도 일반 소리처럼 기본 거리, 강도, 거리 감쇠와 장애물 감쇠를 적용한다.

정보를 수신해도 현재 행동은 취소하지 않는다. 그룹 정보와 전투 이력은 갱신할 수 있지만 실제 행동 변경은 현재 행동 완료 후 재인지·재판단 과정에서 이루어진다.

### 12.3 그룹 집합 규칙

각 AI는 동시에 하나의 그룹에만 속한다. 그룹끼리 교집합을 가지지 않는다.

```text
{A} + {B, C} → {A, B, C}
```

두 그룹 사이에 유효한 공유 연결이 생기면 즉시 합집합으로 병합한다.

연결이 일정 시간 이상 끊기면 현재 연결 상태를 기준으로 여러 그룹이나 개인으로 분리한다.

```text
{A, B, C} → {A, B} + {C}
```

분리된 각 그룹은 분리 시점의 최신 그룹 정보를 복사한 뒤 독립적으로 갱신한다.

### 12.4 최신 정보 규칙

그룹은 가장 최신의 유효한 정보를 사용한다.

비교 기준은 정보 수신 시각이 아니라 원본 정보 발생 시각이다. 전달이 늦어진 오래된 보고가 최근 정보를 덮어쓰지 않도록 한다.

- 더 최근 정보가 기존 위치를 덮어쓴다.
- 동일한 시각이면 직접 시야, 직접 소리, 전달받은 정보 순서로 우선한다.
- 새로운 소리가 더 최근이면 기존 시각 위치를 갱신한다.
- 전투 상태는 위치 정보가 변경되어도 유지한다.
- 이미 전달한 동일 정보는 반복 공유하지 않는다.

전투 이력이 없는 AI가 전투 정보를 수신하면 즉시 전투 상태가 되고 `HasEnteredCombat = true`가 된다.

## 13. AI 판단 구조

판단 입력:

- 현재 AI 상태
- 전투 이력
- 직접 인지한 최신 정보
- 그룹의 최신 정보
- 플레이어와의 거리
- 플레이어의 사격 방향
- 현재 총기와 탄약
- 주변 엄폐물
- 확보 가능한 사격각
- 아군 위치와 목적지
- 이동 가능한 지형

판단 결과:

- 현재 위치 유지
- 엄폐물 이동
- 새로운 사격각 확보
- 측면 이동
- 정면 또는 대각선 접근
- 사격

- 근접 접근

- 아군 정보 공유

## 14. 사격 대응 이동

플레이어가 사격 중이면 플레이어의 조준·사격 방향을 정면 위험 구역으로 사용한다.

이동 후보 평가:

1. 현재 이동 가능한 엄폐·사격 위치 생성
2. 플레이어 사격 방향과 후보 이동 경로의 각도 계산
3. 정면 위험각 안으로 접근하는 후보 제외
4. 측면과 우회 후보 우선 평가
5. 사격 방향에서 충분히 벗어난 후보는 정면·대각선 이동 허용

측면 후보가 없을 때 사용할 대체 행동은 별도로 정의한다.

## 15. 협력 판단

그룹 정보와 아군 목적지를 사용해 다음 행동을 조정한다.

- 다른 AI가 이동하는 동안 현재 위치에서 견제
- 한 AI가 정면에서 압박하는 동안 다른 AI가 측면 이동
- 동일한 엄폐물에 여러 AI가 몰리지 않도록 점유 정보 사용
- 색적 지점을 분배하여 서로 다른 구역 조사
- 그룹이 분리되면 각 그룹이 독립적으로 판단

## 16. 암살·붙잡기 구조

### 16.1 암살 조건 검사

- 대상 상태가 전투가 아님
- 플레이어와 대상 사이 거리가 기준 이내
- 플레이어가 대상의 후방 각도 안에 있음
- 대상이 플레이어를 현재 시야로 확정하지 않음
- 대상이 다른 강제 상호작용 중이 아님

조건을 만족하지 않으면 일반 근접 공격으로 처리한다.

### 16.2 붙잡기

붙잡기 상태에서 허용하는 행동:

- 제한적인 이동
- 암살

플레이어가 피격되면 붙잡기 강제 해제 행동을 실행하고 대상 AI를 방생한다.

암살 행동이 확정되어 플레이어 조작이 잠기는 시점부터 암살 종료 시점까지 무적을 적용한다. 정확한 시작·종료 프레임은 애니메이션과 함께 조정한다.

## 17. 장시간 색적 구조

AI 사이의 최대 거리를 직접 제한하지 않는다. 다음 요소로 색적 범위와 분산을 제어한다.

- 전투 구역 경계
- 마지막 플레이어 위치를 중심으로 한 색적 가능 구역
- 색적 범위 확장 속도
- 색적 목적지 사이의 최소 간격
- 그룹 공유 연결 거리
- 연결 단절 유예 시간

AI가 공유 범위를 벗어나면 그룹이 자연스럽게 분리되며, 장시간 색적 과정에서 적의 밀집도가 낮아진다.

## 18. 지형 기능

지형이 제공해야 하는 상호작용 정보:

- 엄폐 가능 여부와 엄폐 높이
- 웅크리기·엎드리기 가능 구역
- 수풀 은신 구역
- 낮은 장애물 오르기·넘기 연결
- 높은 지형 오르기 연결
- 좁은 통로 연결

AI 이동망에는 엄폐, 오르기, 넘기 정보를 제공하되 좁은 통로 연결은 제공하지 않는다.
