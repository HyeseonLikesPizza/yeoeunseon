## 후보를 줄여도 같은 적을 찾았을까?

**수정한 그리드 검색과 전체 순회를 1,214개 조회에서 비교했고, 결과 불일치는 0이었다.** 시간은 측정하지 않았다.

```text
같은 적 데이터와 검색 위치·반경
├ 전체 순회 → 모든 적에게 거리 검사 → 기준 ID 목록
└ 그리드   → 후보 칸의 적만 거리 검사 → 비교할 ID 목록

양쪽 ID 목록을 정렬해서 비교
→ 누락·불필요한 포함·중복 반환이 있으면 실패
```

순서는 달라도 된다. 다만 중복을 제거한 뒤 비교하지는 않는다. 중복 반환도 오류로 잡기 위해서다. 기준 전체 순회는 그리드의 칸 목록을 읽지 않는다.

## 어떤 조건을 확인했나?

| 조건 | 확인한 의미 |
|---|---|
| `(3.9, 1)` 주변의 `(4.1, 1)` | 다른 칸이어도 반경 안이면 누락하지 않는다 |
| 음수 좌표, 정확히 −4인 좌표 | 음수 칸 번호와 경계 처리가 맞는다 |
| 사각형 모서리, 반경 경계와 그 직후 | 사각형 안이어도 원 밖이면 제외하고, 거리 = 반경은 포함한다 |
| 반경 0, 빈 전장 | 같은 위치만 포함하고 빈 목록도 처리한다 |
| 반경 10m, 칸 폭 4m | 고정된 주변 9칸 밖의 적도 찾는다 |
| 한 칸에 적 20,000명 | 후보가 줄지 않아도 결과는 정확하다. 빠르다는 뜻은 아니다 |
| 칸 이동·같은 칸 내 이동·삭제·추가 | 현재 위치와 생존 상태를 검색 결과에 반영한다 |

이렇게 기대하는 ID를 직접 지정한 조회가 **14개**다. 전체 순회의 결과부터 기대 ID와 같은지 확인한 다음, 수정한 그리드 결과와 비교했다.

추가로 적 20,000명에 대해 다음 조합을 확인했다.

```text
seed 2개: 17, 42
칸 폭 3개: 1m, 4m, 16m
각 조합: 변경 전 100조회 + 이동·삭제·추가 후 100조회

2 × 3 × 200 = 1,200조회
```

좌표는 양수·음수를 포함하는 재현 가능한 데이터이며, 조회 반경은 0·2·10·40m를 사용했다. 변경 후에도 적 수는 20,000명을 유지했다.

각 적이 **현재 칸에 정확히 한 번 등록되었는지**, 삭제한 ID가 남아 있지 않은지도 별도로 검사했다.

## 잘못된 구현도 실제로 잡았나?

수정 코드만 통과하는 것으로 끝내지 않고, 일부러 오답 방식을 실행해 테스트가 누락을 잡는지도 확인했다.

| 일부러 실행한 방식 | 테스트가 잡은 오류 |
|---|---|
| 원래 코드: 정수 변환 + 한 칸만 방문 | 양수의 칸 경계 너머 적 누락 |
| floor만 수정하고 한 칸만 방문 | 음수 계산을 고쳐도 이웃 칸 누락은 남음 |
| 원래 코드로 음수 위치 검색 | 0번 칸을 찾아 −1번 칸의 적 누락 |
| floor + 주변 9칸 고정 | 큰 반경의 적 누락 |

**네 오답 조건 모두 차이를 검출했다.** 로그의 `DETECTED`는 수정 코드가 실패했다는 뜻이 아니라, 의도한 오답을 잡았다는 뜻이다.

```text
SUCCESS / corrected comparisons=1214 / mismatch=0 / deliberate bug detections=4/4
```

→ `floor`와 전체 칸 범위 순회가 각각 필요한 이유를 결과로 확인했다. 같은 데이터에서 후보를 줄여도 포함된 적들은 그대로여야 한다.

## 무엇까지 확인한 것인가?

2026-10-15, Windows MSVC `/utf-8 /O2 /W4 /EHsc /std:c++17`로 경고 없이 빌드하고 실행했다. 일반 C++ 단일 Thread 테스트이며 Unreal Automation Test가 아니다.

테스트는 칸에 ID 목록을 저장하고 별도 Enemy 저장소에서 현재 상태를 읽는다. 본문의 `Grid.At()` 설명용 발췌와 저장 형태는 다르지만, **floor → 사각형의 칸 범위 → 거리 제곱 판정**이라는 검색 방식은 같다. 원과 칸의 겹침을 추가 검사하는 최적화는 구현하지 않았다.

검사한 것은 **위 조건의 결과와 등록 일관성**이다. 모든 부동소수점 입력의 수학적 정확성, 동시 접근, Unreal 객체 수명, 성능 향상을 증명한 것은 아니다. 유한한 좌표·음수가 아닌 반경과 정수 칸 번호의 안전 범위를 전제로 한다.

코드: [[GridRadiusSearchTest.cpp]] · 로그: [[GridRadiusSearchTest_Run1.txt]]

`.obsidian`과 `tmp`가 있는 학습 폴더에서 PowerShell로 실행한다. 빌드 스크립트는 기본 소스를 자동으로 찾고, 생성물은 `tmp`에 둔다.
