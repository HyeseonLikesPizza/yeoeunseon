## 문제 상황

언리얼 액션 게임에서 상점 구매와 퀘스트 보상 지급을 병렬 Task로 처리하고 있다.

평소에는 문제가 없지만, 플레이어가 아이템을 구매하는 순간 퀘스트 보상까지 들어오면 게임이 아주 드물게 멈춘다.

```text
일반 플레이                  → 문제 없음
상점 구매만 실행             → 문제 없음
퀘스트 보상만 실행           → 문제 없음
구매와 보상이 동시에 실행     → 간헐적으로 멈춤
```

크래시 로그는 남지 않으며 CPU 사용률도 높지 않다. 멈춘 뒤에는 해당 프레임이 끝나지 않는다.

---

플레이어의 재화와 인벤토리는 서로 다른 Lock으로 보호한다.

```cpp
struct FPlayerStateData
{
    FCriticalSection Lock;
    int32 Gold = 0;
};

struct FInventoryData
{
    FCriticalSection Lock;
    TArray<int32> ItemIds;
};
```

상점 구매에서는 골드가 충분한지 확인한 뒤 골드를 차감하고 아이템을 추가한다.

```cpp
bool FShopSystem::PurchaseItem(int32 ItemId, int32 Price)
{
    FScopeLock PlayerGuard(&PlayerState.Lock);

    if (PlayerState.Gold < Price)
    {
        return false;
    }

    Inventory.AddItem(ItemId);
    PlayerState.Gold -= Price;

    return true;
}
```

`Inventory.AddItem()` 내부에서는 인벤토리를 변경한 뒤 Delegate를 호출한다.

```cpp
void FInventorySystem::AddItem(int32 ItemId)
{
    FScopeLock InventoryGuard(&Inventory.Lock);

    Inventory.ItemIds.Add(ItemId);
    OnInventoryChanged.Broadcast();
}
```

장비 능력치를 갱신하는 시스템이 이 Delegate를 구독하고 있다.

```cpp
void FEquipmentSystem::HandleInventoryChanged()
{
    FScopeLock PlayerGuard(&PlayerState.Lock);

    RecalculateEquipmentStats(PlayerState, Inventory);
}
```

퀘스트 보상 지급도 같은 `AddItem()`을 사용한다.

```cpp
void FQuestSystem::GrantReward(int32 RewardItemId)
{
    Inventory.AddItem(RewardItemId);
}
```

두 작업은 다음처럼 실행되고, Game Thread는 이번 프레임에 결과가 필요해 완료를 기다린다.

```cpp
UE::Tasks::FTask PurchaseTask = UE::Tasks::Launch(
    UE_SOURCE_LOCATION,
    [&]
    {
        ShopSystem.PurchaseItem(ItemId, Price);
    });

UE::Tasks::FTask RewardTask = UE::Tasks::Launch(
    UE_SOURCE_LOCATION,
    [&]
    {
        QuestSystem.GrantReward(RewardItemId);
    });

UE::Tasks::Wait(TArray{PurchaseTask, RewardTask});
```

---

멈춘 순간 디버거에서 확인한 호출 스택은 다음과 같았다.

```text
Worker A — PurchaseTask

FWindowsCriticalSection::Lock
FInventorySystem::AddItem
FShopSystem::PurchaseItem


Worker B — RewardTask

FWindowsCriticalSection::Lock
FEquipmentSystem::HandleInventoryChanged
OnInventoryChanged.Broadcast
FInventorySystem::AddItem
FQuestSystem::GrantReward


Game Thread

UE::Tasks::Wait
```

각 시스템을 담당한 개발자들은 다음과 같이 말했다.

```text
“상점 구매와 퀘스트 보상 코드는 서로 다른데 왜 같이 실행할 때만 멈추죠?”

“각 기능을 따로 테스트할 때는 한 번도 재현되지 않았습니다.”

“FScopeLock을 사용하고 있어서 Unlock을 빠뜨린 곳은 없어 보입니다.”
```

### 해결 조건

게임이 멈춘 원인을 Thread의 대기 관계와 Lock 획득 경로를 따라 설명하고 구조를 개선해라.

다음 요구사항은 유지해야 한다.

```text
상점 구매와 퀘스트 보상은 동시에 요청될 수 있다.

골드 차감과 구매 아이템 추가는 중간 상태가 노출되지 않도록 처리한다.

PlayerState와 Inventory의 공유 상태는 계속 안전하게 보호한다.

인벤토리 변경 알림도 유지한다.
```
