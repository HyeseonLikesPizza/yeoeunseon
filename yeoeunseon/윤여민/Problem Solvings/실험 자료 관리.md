## 문제별로 함께 보관

```text
문제 이름/
├ 학습 문서.md
└ 실험/
   ├ 테스트 코드.cpp
   ├ 검증 기록.md
   ├ 실행 로그·요약 CSV
   └ 재현/                 빌드·수집·해석 스크립트
```

학습 문서를 먼저 읽고, 필요한 경우 같은 문제의 실험으로 내려간다. 공용 Tests 폴더에 서로 다른 문제의 자료를 쌓지 않는다.

## Git에 남기는 것

- 학습 문서, 코드, 재현 스크립트.
- 판단의 근거가 된 실행 로그와 요약 CSV.
- 실제 조건과 측정하지 못한 범위.

생성물은 `.obsidian`이 있는 학습 폴더의 **`tmp/`**에 둔다. exe·obj·pdb·Assembly와 VTune 수집 DB·중간 보고서는 Git에서 제외한다.

vector/map 실험의 상세 보고서는 `실험/VTuneVector*/원본 보고서/`에도 로컬 보관했다. 이 폴더 역시 Git에서 제외한다. **무시한다고 삭제되는 것은 아니지만, 다른 PC에서 clone하면 이 원본들은 없다.** 필요한 원본은 별도로 백업한다.

## 재현할 때

`실험/재현/Build*.cmd`는 인수 없이 실행하면 같은 실험 폴더의 기본 소스를 빌드한다. VS 2022 Community 설치 경로를 사용하므로 다른 환경에서는 경로를 조정한다.

VTune은 `Build*Profile.cmd` → 관리자 권한의 `VTune*Captures.cmd` → `Read*.ps1` → `Summarize*.ps1` 순서다. 조회 순서 실험은 `ReadVTuneOrderCaptures.ps1` 다음에 `ReadVTuneOrderModules.ps1`도 실행한다. 수집 폴더가 이미 있으면 덮어쓰지 않고 중단한다.

이전에 수집한 데이터의 심볼을 다시 읽을 수 있도록, 해당 실행 파일·PDB를 보관한 뒤 재빌드한다. 새 capture의 요약을 확인하고 문서에 반영하기 전에는 기존 증거를 새 결과로 교체하지 않는다.

기존 PDB에는 이동 전 소스 경로가 기록되어 있다. VTune에서 소스가 안 보이면 Source Search에 새 `실험` 폴더를 추가한다. 원본 수집 데이터와 실행 파일을 지울 필요는 없다.

## 커밋은 문제 단위로

한 문제의 문서·코드·검증 기록을 함께 선택해 커밋한다. 다른 문제의 미완성 변경까지 한 번에 넣지 않는다. 목차를 함께 수정했다면 그 문제와 관련된 줄을 포함한다.

이번 폴더 정리에서는 파일 이동과 링크·경로만 정리했다. 커밋·푸시는 별도로 진행한다.
