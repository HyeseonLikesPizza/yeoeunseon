# C++ 캐스팅 4종

> [!summary]
> **C++ 캐스팅 4종은 “어떤 의도로 타입을 바꾸는지”를 코드에 드러내기 위해 나뉜 문법이다.**
>
> ```text
> static_cast      = 논리적으로 가능한 일반 변환
> dynamic_cast     = 실제 객체 타입을 런타임에 확인하는 다운캐스팅
> const_cast       = const/volatile 속성 제거 또는 추가
> reinterpret_cast = 같은 주소/비트를 전혀 다른 타입처럼 재해석
> ```
>
> C 스타일 캐스팅 `(Type)Value`보다 C++ 캐스팅을 쓰는 이유는 변환 의도를 더 명확하게 남기기 위해서다.

---

## 핵심 정리

```text
1. static_cast는 가장 일반적인 변환이다.
2. dynamic_cast는 상속 관계에서 실제 객체 타입을 런타임에 확인한다.
3. const_cast는 const를 제거할 수 있지만, 원래 const 객체를 수정하면 안 된다.
4. reinterpret_cast는 주소나 비트를 다른 타입처럼 해석하는 저수준 캐스트다.
5. 다운캐스팅은 static_cast보다 dynamic_cast가 안전하지만 RTTI와 다형 타입 조건이 필요하다.
6. C 스타일 캐스팅은 의도가 섞여 보이므로 C++ 캐스팅 4종을 명시적으로 쓰는 편이 좋다.
7. Unreal의 UObject 계열은 보통 dynamic_cast 대신 Cast<T>()를 사용한다.
```

구분 기준:

```text
캐스팅을 볼 때는 “값 변환인가, 타입 확인인가, const 제거인가, 메모리 재해석인가?”를 먼저 구분한다.
```

---

## 캐스팅 종류

| 캐스트 | 핵심 질문 | 대표 사용 |
| --- | --- | --- |
| `static_cast` | 컴파일 단계에서 논리적으로 변환 가능한가? | 숫자 변환, 업캐스팅, 명시적 다운캐스팅 |
| `dynamic_cast` | 실제 객체가 그 타입이 맞는가? | 안전한 다운캐스팅 |
| `const_cast` | `const` 속성만 바꾸려는가? | 오래된 C API 호출 |
| `reinterpret_cast` | 같은 메모리를 전혀 다른 타입처럼 볼 것인가? | 저수준 주소 변환, 시스템 코드 |

---

## 왜 C 스타일 캐스팅을 피할까?

C 스타일 캐스팅은 짧다.

```cpp
int Value = (int)Pi;
Player* P = (Player*)CharacterPtr;
char* Text = (char*)ReadOnlyText;
```

하지만 어떤 의도로 변환했는지 잘 드러나지 않는다.

```text
숫자 변환인가?
상속 관계 캐스팅인가?
const 제거인가?
전혀 다른 포인터 재해석인가?
```

C++ 캐스팅은 이 의도를 문법으로 나눈다.

```cpp
static_cast<int>(Pi);
dynamic_cast<Player*>(CharacterPtr);
const_cast<char*>(ReadOnlyText);
reinterpret_cast<std::uintptr_t>(Pointer);
```

코드가 조금 길어지지만, 위험한 변환을 검색하고 리뷰하기 쉬워진다.

---

## 1. `static_cast`

`static_cast`는 가장 일반적으로 쓰는 캐스팅이다.

컴파일러가 “이 변환은 문법적으로 가능한 관계다”라고 판단할 수 있을 때 사용한다.

---

## `static_cast`: 숫자 타입 변환

```cpp
double Pi = 3.14;
int Value = static_cast<int>(Pi);
```

결과:

```text
Value = 3
```

소수점이 사라지는 것처럼 값 손실이 있을 수 있다.

`static_cast`는 이런 손실을 막아주는 것이 아니라, 개발자가 의도적으로 변환했다는 것을 표시한다.

---

## `static_cast`: 업캐스팅

자식 객체를 부모 포인터로 보는 것은 안전한 변환이다.

```cpp
class Character
{
public:
    virtual ~Character() = default;
};

class Player : public Character
{
};

Player* PlayerPtr = new Player();
Character* CharacterPtr = static_cast<Character*>(PlayerPtr);
```

```text
Player는 Character이기도 하다.
```

이런 변환은 보통 암시적으로도 가능하다.

```cpp
Character* CharacterPtr = PlayerPtr;
```

상속과 실제 객체 타입 기준 호출은 [[가상 함수]]와도 연결된다.

---

## `static_cast`: 다운캐스팅

부모 포인터를 자식 포인터로 바꾸는 것도 `static_cast` 문법상 가능할 수 있다.

```cpp
Character* CharacterPtr = GetCharacter();
Player* PlayerPtr = static_cast<Player*>(CharacterPtr);
```

하지만 `CharacterPtr`가 실제로 `Player` 객체를 가리키는지는 검사하지 않는다.

```text
컴파일러
→ 상속 관계는 있네. 변환은 허용.

런타임
→ 실제 객체가 Player인지 확인하지 않음.
```

실제 객체가 `Player`가 아니라면 이후 사용은 정의되지 않은 동작으로 이어질 수 있다.

```cpp
PlayerPtr->Attack(); // 실제 객체가 Player가 아니면 잘못된 접근
```

> [!important]
> `static_cast` 다운캐스팅은 “내가 실제 타입을 확실히 알고 있다”는 전제가 있을 때만 사용한다. 확실하지 않다면 `dynamic_cast`나 엔진/프레임워크의 안전한 캐스팅 함수를 사용한다.

---

## 2. `dynamic_cast`

`dynamic_cast`는 상속 관계에서 실제 객체 타입을 런타임에 확인한다.

주로 부모 포인터나 부모 참조를 자식 타입으로 바꿀 때 사용한다.

```cpp
Character* CharacterPtr = GetCharacter();

if (Player* PlayerPtr = dynamic_cast<Player*>(CharacterPtr))
{
    PlayerPtr->Attack();
}
```

실제 객체가 `Player`이면 성공한다.

실제 객체가 `Player`가 아니면 포인터 캐스팅은 `nullptr`을 반환한다.

```text
CharacterPtr가 실제로 Player 객체를 가리킴
→ Player* 반환

CharacterPtr가 실제로 Monster 객체를 가리킴
→ nullptr 반환
```

### 참조로 `dynamic_cast`하면?

참조는 `nullptr`이 될 수 없다.

그래서 실패하면 예외를 던진다.

```cpp
try
{
    Player& PlayerRef = dynamic_cast<Player&>(CharacterRef);
}
catch (const std::bad_cast&)
{
}
```

### 필요한 조건

`dynamic_cast`가 실제 타입을 확인하려면 기반 클래스가 **다형 타입(polymorphic type)**이어야 한다.

쉽게 말해 기반 클래스에 `virtual` 함수가 하나 이상 있어야 한다.

```cpp
class Character
{
public:
    virtual ~Character() = default;
};
```

그리고 RTTI(Runtime Type Information)가 활성화되어 있어야 한다.

```text
virtual 함수 있음
→ 객체가 런타임 타입 정보를 가질 수 있음
→ dynamic_cast가 실제 타입을 확인할 수 있음
```

---

## 3. `const_cast`

`const_cast`는 `const` 또는 `volatile` 속성을 제거하거나 추가할 때 사용한다.

가장 흔한 상황은 오래된 C API가 `char*`를 요구하지만 실제로 내용을 수정하지 않는 경우다.

```cpp
void LegacyPrint(char* Text);

const char* Name = "Player";
LegacyPrint(const_cast<char*>(Name));
```

하지만 이 코드는 조심해야 한다.

`const_cast`는 타입에서 `const` 표시를 지울 뿐, 원래 객체가 수정 가능한지까지 바꿔주지 않는다.

```cpp
const int Value = 10;
int* Ptr = const_cast<int*>(&Value);

// *Ptr = 20; // 원래 const 객체를 수정하려는 것이므로 정의되지 않은 동작
```

반대로 원래 객체가 수정 가능한데, 중간에 `const`로 보였던 경우는 수정 가능하다.

```cpp
int Value = 10;
const int& Ref = Value;

int& MutableRef = const_cast<int&>(Ref);
MutableRef = 20; // 원래 객체가 const가 아니므로 가능
```

정리:

```text
const_cast는 const 표시만 바꾼다. 원래 const 객체를 수정 가능하게 만들어주는 마법은 아니다.
```

## 4. `reinterpret_cast`

`reinterpret_cast`는 같은 주소나 비트를 전혀 다른 타입처럼 해석하겠다는 캐스팅이다.

```cpp
int Value = 10;
std::uintptr_t Address = reinterpret_cast<std::uintptr_t>(&Value);
```

포인터를 정수 주소값으로 바꾸거나, 저수준 시스템 코드에서 타입을 강제로 재해석할 때 사용한다.

하지만 일반 코드에서는 거의 피하는 편이 좋다.

### 왜 위험할까?

`reinterpret_cast`는 객체의 의미를 안전하게 변환하지 않는다.

```cpp
double Pi = 3.14;
int* Ptr = reinterpret_cast<int*>(&Pi);
```

이 코드는 `double` 객체가 있는 메모리를 `int` 객체가 있는 것처럼 보겠다는 뜻이다.

문제가 될 수 있는 이유:

```text
타입 크기가 다를 수 있음
정렬(alignment)이 맞지 않을 수 있음
객체의 실제 타입과 읽는 타입이 다름
strict aliasing 규칙을 어길 수 있음
```

즉 “값 변환”이 아니라 “메모리 해석 변경”이다.

```text
static_cast<int>(3.14)
→ double 값을 int 값으로 변환

reinterpret_cast<int*>(&Pi)
→ double 메모리를 int 메모리처럼 보겠다고 주장
```

> [!caution]
> 바이트 해석이나 직렬화가 목적이라면 `reinterpret_cast`로 구조체 포인터를 바로 덮어씌우기보다 `std::memcpy`, 명시적 파싱, C++20 `std::bit_cast` 같은 방법을 먼저 고려한다.

## 포인터 캐스팅 비교

상속 구조가 있다고 하자.

```cpp
class Character
{
public:
    virtual ~Character() = default;
};

class Player : public Character
{
public:
    void Attack() {}
};

class Monster : public Character
{
};
```

```cpp
Character* Ptr = new Monster();
```

### `static_cast`

```cpp
Player* P = static_cast<Player*>(Ptr);
P->Attack(); // 위험: 실제 객체는 Monster
```

`static_cast`는 상속 관계만 보고 허용한다.

실제 객체가 `Player`인지 확인하지 않는다.

### `dynamic_cast`

```cpp
Player* P = dynamic_cast<Player*>(Ptr);

if (P)
{
    P->Attack();
}
```

실제 객체가 `Player`가 아니므로 `P`는 `nullptr`이 된다.

```text
static_cast
→ 내가 맞다고 확신하고 변환

dynamic_cast
→ 실제 타입을 확인하고 맞을 때만 변환
```

## Unreal에서는 `Cast<T>()`

Unreal의 `UObject` 계열에서는 보통 C++ `dynamic_cast`를 직접 사용하지 않는다.

대신 Unreal의 리플렉션 정보를 이용하는 `Cast<T>()`를 사용한다.

```cpp
AActor* Actor = GetActor();

if (AMyCharacter* Character = Cast<AMyCharacter>(Actor))
{
    Character->Jump();
}
```

실패하면 `nullptr`을 반환한다.

```text
dynamic_cast
→ C++ RTTI 기반

Unreal Cast<T>()
→ Unreal Reflection 기반
```

Unreal 코드에서는 `UObject` 타입 확인에 `IsA()`나 `Cast<T>()`를 주로 사용한다.

```cpp
if (Object && Object->IsA(UMyObject::StaticClass()))
{
}
```

이 차이는 Unreal의 [[Reflection]] 시스템을 이해하면 더 잘 보인다.

## 언제 무엇을 쓸까?

| 상황 | 추천 |
| --- | --- |
| 숫자 변환 | `static_cast` |
| 안전한 업캐스팅 | 보통 암시적 변환 또는 `static_cast` |
| 실제 타입이 확실한 다운캐스팅 | `static_cast` 가능 |
| 실제 타입을 확인해야 하는 다운캐스팅 | `dynamic_cast` 또는 프레임워크 캐스팅 |
| 오래된 API가 `const` 없는 포인터를 요구함 | 신중하게 `const_cast` |
| 포인터를 정수 주소값으로 저장 | 제한적으로 `reinterpret_cast` |
| 원시 바이트를 구조체로 읽고 싶음 | `memcpy`, 명시적 파싱, `std::bit_cast` 우선 고려 |
| Unreal `UObject` 캐스팅 | `Cast<T>()` |

---

## 정리

1. C++ 캐스팅 4종은 변환 의도를 명확히 나누기 위한 문법이다.
2. `static_cast`는 일반 변환과 확신 있는 상속 변환에 사용한다.
3. `dynamic_cast`는 실제 객체 타입을 런타임에 확인한다.
4. `dynamic_cast`는 다형 타입과 RTTI가 필요하며 실패 시 포인터는 `nullptr`이 된다.
5. `const_cast`는 `const` 표시를 제거할 수 있지만 원래 const 객체를 수정하면 안 된다.
6. `reinterpret_cast`는 메모리 재해석이므로 일반 코드에서는 최대한 피한다.
7. Unreal의 `UObject` 계열은 보통 `dynamic_cast` 대신 `Cast<T>()`를 사용한다.
